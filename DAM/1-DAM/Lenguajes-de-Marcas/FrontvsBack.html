Cliente, servidor y un lenguaje común para comunicarse

Programación · DAM 1º · Arquitectura del Software

Una web funciona porque varias piezas hablan el mismo idioma: el front (cliente), el back (servidor) y el HTTP que usan para comunicarse entre ellos.

Front, HTTP y Back: las tres piezas

FRONT (Cliente)

Es lo que usa la persona. Muestra la interfaz y permite interactuar.

HTTP

Es el lenguaje común que usan cliente y servidor para comunicarse.

BACK (Servidor)

Procesa las peticiones, ejecuta lógica (aplicación) y devuelve datos o archivos.

El front no siempre es una web

Normalmente es una aplicación web en el navegador, pero también puede ser:

  • App móvil (nativa)
  • App de escritorio (nativa)
  • Reloj inteligente
  • Otros dispositivos

Petición y respuesta HTTP

El cliente pide algo con una petición HTTP (por ejemplo, pedir una página) y el servidor contesta con una respuesta HTTP (por ejemplo, enviando archivos).

Petición HTTP →

Ej: pedir una página.

GET /inicio HTTP/1.1
Host: midominio.com

← Respuesta HTTP

Ej: enviar archivos.

HTTP/1.1 200 OK
Content-Type: text/html
...
[datos de la página]

¿Qué puede hacer el back (servidor)?

  • Servir archivos estáticos (HTML, CSS, JS, imágenes, ...)
  • Ejecutar código del servidor (por ejemplo, en Node.js, Python, PHP, Java, ...)
  • Acceder a bases de datos
  • Devolver la respuesta al cliente

¿Qué archivos tiene una app de front (web)?

Normalmente está compuesta por varios archivos que se alojan en un servidor y el navegador debe traerlos primero.

HTML

Estructura el contenido de la página.

<h1>Hola</h1>

CSS

Define el estilo y el diseño.

h1 { color: blue; }

JavaScript

Añade interactividad y comportamiento.

console.log("Hola");

Recursos

Imágenes, fuentes, iconos, vídeos, etc.

¿Cómo se carga una página?

Cuatro pasos que se repiten cada vez que visitas una web... y ocurren en cuestión de segundos.

1
Petición
El navegador hace una petición HTTP al servidor.
2
Respuesta
El servidor responde enviando los archivos (HTML, CSS, JS, recursos...) a través de HTTP.
3
Construcción
El navegador descarga los archivos, los interpreta y construye la página.
4
Interacción
El usuario ve la página y puede interactuar.

¡Todo esto ocurre en segundos!

Idea clave: el front y el back pueden estar en equipos distintos, se comunican usando HTTP, y el navegador (o cualquier otro dispositivo) trae los archivos necesarios del servidor para mostrar la aplicación.

Diferentes tecnologías, la misma idea: ¡comunicar y compartir!
