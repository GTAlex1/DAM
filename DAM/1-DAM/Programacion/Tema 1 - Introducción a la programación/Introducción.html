¿Qué es un algoritmo?

Un algoritmo es una secuencia de pasos sencillos, diseñados para resolver un problema, que pueda realizar un ordenador. Para que un conjunto de pasos merezca llamarse algoritmo, tiene que cumplir 5 reglas:

Finito

Tiene que acabar siempre tras un número finito de pasos.

Preciso

Cada paso debe definirse de modo exacto, sin ambigüedad.

Entrada

Requiere datos iniciales (el caso particular del problema).

Salida

Genera un conjunto de objetos como resultado final.

Tiempo finito

Sus acciones deben efectuarse en un intervalo temporal acotado.

Ejemplo: físico vs. digital

La misma idea de "algoritmo" aparece en lo cotidiano y en el código, solo cambia el nivel de precisión exigido:

La metáfora de la caja negra

Un algoritmo actúa como un mecanismo cerrado: entran datos brutos y salen resultados procesados. No hace falta ver por dentro para usarlo — solo conocer qué entra y qué sale.

SUELDOHORA →
HORASTRAB →
ALGORITMO: CÁLCULO DE SALARIO 1. Si horas ≤ 40: multiplicar por sueldo.
2. Si horas > 40: paga regular (40h) + paga extra (dif × 2).
3. Sumar ambos para el sueldo total.
→ SUELDOTOTAL

Traduciendo la lógica a instrucciones

Para que el ordenador entienda la caja negra, hay que dictar exactamente lo que queremos usando un lenguaje de programación. Un programa es simplemente esta secuencia de instrucciones — este ejemplo está en Pascal:

program calculosueldo;
var sueldohora, horastrab: integer;
    sueldototal, pagaregular, pagaextra: integer;
begin
  readln(sueldohora);       // Entrada de datos (ingresando a la caja negra)
  readln(horastrab);
  if (horastrab <= 40) THEN
    sueldototal := sueldototal * horastrab
  else
    begin                    // Control de flujo (la lógica de decisión)
      pagaregular := sueldohora * (horastrab - 40);
      pagaextra := 2 * sueldohora * (horastrab - 40);
      sueldototal := pagaregular + pagaextra
    end;
  writeln(sueldototal)
end.

La línea var ... es la declaración de datos (preparando la memoria) antes de poder usarlos.

Puesta a punto: el ciclo de vida del programa

1
Edición
El programa fuente se graba en un soporte mediante un editor.
2
Compilación
El código se traduce a programa objeto y se verifica la sintaxis.
3
Montaje
El linker une el programa con rutinas del sistema y librerías.
4
Ejecución
El ejecutable se prueba con datos para verificarlo.
5
Documentación
Tras el éxito, se documenta para el mantenimiento.

Si hay errores (depuración), se repiten las fases desde la edición.

Características del código profesional

Se pueden construir múltiples algoritmos para un mismo problema. El diseño óptimo — el "programa ideal" — se evalúa bajo estos criterios:

Legibilidad

De fácil lectura y comprensión humana.

Modificabilidad

Arquitectura fácil de mantener y alterar.

Portabilidad

Funciona igual en distintos sistemas.

Eficiencia

Aprovecha los recursos al máximo.

Estructurado

Sigue las estructuras básicas de control.

Modularidad

Subdividido en bloques independientes.

Traductores: intérpretes vs. compiladores

Todo lenguaje de alto nivel debe transformarse a código máquina. Existen dos estrategias para lograrlo:

Intérpretes — traducción en vivo

Sentencia fuente → intérprete → ejecución inmediata → siguiente sentencia. Traducen y ejecutan a la vez, línea por línea. No generan archivo intermedio.

Compiladores — traducción en bloque

Programa fuente completo → compilador → código objeto → montador (linker) → programa ejecutable. Traducen todo el código antes de ejecutar. Generan un programa objeto.

Técnicas de programación: paradigmas

Programación modular

El programa se divide en partes independientes. Permite a varios programadores trabajar a la vez, reduciendo el tiempo de diseño.

Programación estructurada

Uso estricto de tres estructuras básicas de control (secuencia, selección, iteración) para facilitar escritura y mantenimiento.

Orientada a objetos (OOP)

Diseñada para maximizar la reutilización de código mediante jerarquías de objetos. Lo importante no es cómo, sino cuáles son los objetos.

Átomos del sistema: datos, constantes y variables

Constante

Su valor permanece invariable durante la ejecución. Ej: PI = 3.14

Variable

Su valor puede modificarse y necesita un nombre de referencia. Ej: RADIO = 5

Tablas de verdad: rutas lógicas

AND (Y)

Ambas entradas deben ser V para salida V.
(V+V=V, V+F=F, F+V=F, F+F=F)

OR (O)

Al menos una entrada V da salida V.
(V+V=V, V+F=V, F+V=V, F+F=F)

NOT (NO)

Invierte la señal.
(V → F, F → V)

Evaluación práctica

Valores: a = 10, b = 12, c = 13 — Expresión: not (a == c) and (c > b)

Paso 1:  not (F)  →  and (V)
Paso 2:      (V)  →  and (V)
Resultado:           V (Verdadero)

El motor lógico en acción

¿Cómo dirigen los "átomos" lógicos el comportamiento de todo un algoritmo? Así funciona la toma de decisiones, con horastrab = 45:

Evaluación lógica:  (horastrab <= 40)   →   Resultado: FALSE

  THEN (TRUE)  → sueldototal := sueldohora * horastrab
  ELSE (FALSE) → pagaregular := sueldohora * 40;
                 pagaextra := ...

Las expresiones lógicas son los "interruptores" que deciden qué camino toma el programa dentro de la caja negra.
